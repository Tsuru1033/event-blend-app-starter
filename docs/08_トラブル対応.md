# トラブル対応

問題が発生した場合は、推測だけで設定やパスワードを繰り返し変更しないでください。

次の順番で原因を確認します。

1. 画面に表示されたエラー全文を確認する
2. GitHub、Vercel、Supabase、ブラウザーのどこで発生しているか確認する
3. 接続先と環境変数を確認する
4. ログや通信結果を確認する
5. 原因を特定してから変更する

---

## 最初に確認するURL

- GitHubの自分専用アプリ保管ページ
- Vercelの対象アプリ管理画面
- VercelのProduction固定URL
- Supabaseの対象プロジェクト

複数のテスト環境や本番環境がある場合は、現在操作している環境名を必ず確認してください。

---

## アプリが真っ白になる

### 主な原因

- `VITE_SUPABASE_URL`がURL形式になっていない
- Value欄に変数名やイコール記号まで貼り付けた
- URLの前後に引用符、空白、改行がある
- JavaScriptの実行エラーがある

### 確認する場所

Vercelで次の順に進みます。

```text
対象のアプリ
→ Settings
→ Environments
→ Production
→ Environment Variables
```

`VITE_SUPABASE_URL`のValueは、次の形式にします。

```text
https://プロジェクトID.supabase.co
```

次の形式は誤りです。

```text
VITE_SUPABASE_URL=https://プロジェクトID.supabase.co
```

### Consoleで確認する

公開アプリを開き、次の順に進みます。

```text
F12
→ Console
```

次のエラーがある場合は、Supabase URLを確認してください。

```text
Invalid supabaseUrl: Must be a valid HTTP or HTTPS URL
```

修正後はProductionを再デプロイし、ブラウザーを強制再読み込みしてください。

```text
Ctrl + Shift + R
```

## 集計者がログインできない

### 最初に確認すること

- SupabaseのAuthenticationに集計者ユーザーが存在する
- メールアドレスとパスワードが正しい
- ユーザー作成時に`Auto confirm user`を有効にした
- Supabaseプロジェクトが停止していない
- Vercelの環境変数変更後に再デプロイした

### Project URLとPublishable keyを確認する

Vercelでは次の2つを使用します。

```text
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
```

2つの値は、必ず同じSupabaseプロジェクトから取得してください。

```text
VITE_SUPABASE_URL
→ https://プロジェクトID.supabase.co
```

```text
VITE_SUPABASE_PUBLISHABLE_KEY
→ sb_publishable_で始まるキー
```

Secret key、`sb_secret_`で始まるキー、service_roleキーは使用しないでください。

### アプリの接続先を確認する

公開アプリで次の順に進みます。

```text
F12
→ Network
→ ログインする
→ token?grant_type=password
→ Headers
→ Request URL
```

Request URLは次のような形式です。

```text
https://プロジェクトID.supabase.co/auth/v1/token?grant_type=password
```

SupabaseのConnect画面にあるProject URLと、Request URLの`https://`から`.supabase.co`までを比較してください。

1文字でも違う場合は、Vercelが別のSupabaseプロジェクトを参照しています。

正しいProject URLとPublishable keyへ修正し、Productionを再デプロイしてください。

パスワードを作り直す前に、接続先が一致していることを確認してください。

## パスワードを忘れた

集計者は、メールアドレスとパスワードでログインします。

UIDではログインできません。

Supabaseで次の順に進みます。

```text
Authentication
→ Users
→ 集計者ユーザー
```

パスワード再設定メールを送信できます。

再設定メールのリンクが開けない場合は、SupabaseのSite URLとRedirect URLsが、VercelのProduction固定URLになっているか確認してください。

急ぎの場合は、集計者ユーザーを削除し、新しいパスワードで作り直す方法があります。

ユーザーを作り直すとUIDが変わります。その場合は、次のSQLに設定するUIDも更新してください。

```text
supabase/admin_delete_policy_template.sql
```

## `permission denied`またはエラーコード42501

### 主な原因

- テーブル権限の`GRANT`が不足している
- RLSポリシーが不足している
- ログイン状態と対象ロールが一致していない
- 初期設定SQLを最後まで実行していない

`GRANT`とRLSは別々の設定です。片方だけでは正常に動かない場合があります。

### 確認するファイル

```text
supabase/migrations/202608280001_initial_schema.sql
```

SupabaseのSQL Editorで初期設定SQLを実行し、次の表示を確認してください。

```text
Success. No rows returned
```

### 全回答削除だけ失敗する場合

次を確認してください。

- 集計者としてログインしている
- 現在の集計者UIDと削除ポリシーのUIDが一致している
- 集計者ユーザーを作り直した後に削除ポリシーを更新した

使用するSQLは次のファイルです。

```text
supabase/admin_delete_policy_template.sql
```

## `Failed to fetch`

### 主な原因

- インターネット接続が切れている
- SupabaseのProject URLが誤っている
- Publishable keyが誤っている
- Project URLとPublishable keyが別のプロジェクト
- Supabaseプロジェクトが停止中
- 会社ネットワークやプロキシが通信を遮断している

### 確認手順

1. Supabaseプロジェクトが`Healthy`か確認する
2. Project URLとPublishable keyを同じプロジェクトからコピーし直す
3. Vercelへ保存する
4. Productionを再デプロイする
5. ブラウザーを強制再読み込みする
6. ConsoleとNetworkを確認する

---

## `ERR_TUNNEL_CONNECTION_FAILED`

このエラーは、Supabaseがパスワードを拒否したとは限りません。

会社ネットワーク、プロキシ、セキュリティ製品などにより、Supabaseへの通信が完了していない可能性があります。

### 確認すること

- 別のブラウザーで試す
- スマートフォンのWi-Fiを切り、モバイル通信で試す
- SupabaseのProject URLを新しいタブで直接開けるか確認する
- NetworkのRequest URLが正しいか確認する
- SupabaseのAuthログにログイン要求が記録されているか確認する

Project URLへ直接到達できるか確認する場合は、末尾に次を付けます。

```text
/auth/v1/health
```

例：

```text
https://プロジェクトID.supabase.co/auth/v1/health
```

APIキーなしで開いた場合、`No API key found`と表示されることがあります。この表示は、Supabaseのホストへ到達できていることを示します。

通信エラーが出ている間は、ユーザーやパスワードを繰り返し作り直さないでください。

## Supabaseプロジェクトが停止している

Supabaseのプロジェクト一覧で、次のような表示が出る場合があります。

```text
Paused
Project is restoring
Project is coming up
```

### 対応

- `Paused`の場合はプロジェクトを再開する
- `Project is restoring`の場合は復元完了を待つ
- `Project is coming up`の場合は起動完了を待つ

表示が消えても、Authやデータベースが利用可能になるまで数分かかる場合があります。

復旧完了後に、アプリのログインと回答取得を再確認してください。

---

## GitHubを更新したのにアプリが変わらない

次を確認してください。

- 正しいGitHubのページを編集した
- テンプレート本体とテスト版を取り違えていない
- 変更を`main`へ保存した
- Vercelが対象のGitHubページと接続されている
- Vercelの最新Deploymentが`Ready`になっている
- Productionの固定URLを開いている
- ブラウザーを再読み込みした

古い表示が残る場合は、次を押してください。

```text
Ctrl + Shift + R
```

GitHubテンプレートから作成したアプリは、テンプレート本体とは独立しています。

テンプレート本体を更新しても、すでに作成済みのテスト版や提供先アプリへ自動反映されません。

---

## VercelへGitHubのアプリが表示されない

VercelのImport画面で次を押します。

```text
Adjust GitHub App Permissions
```

GitHub側で、Vercelに利用を許可するアプリを追加します。

既存の本番アプリを削除せず、追加したいアプリを選択して保存してください。

---

## 参加人数を保存できない

次を確認してください。

- 集計者としてログインしている
- 入力人数が1～30名の範囲
- `event_settings`テーブルが存在する
- 初期設定SQLを最新状態で実行した
- Vercelが正しいSupabaseへ接続している
- Supabaseプロジェクトが停止していない

参加人数は次のテーブルへ保存されます。

```text
event_settings
```

初期設定SQLは次です。

```text
supabase/migrations/202608280001_initial_schema.sql
```

---

## 参加人数を変更しても表示が変わらない

次を確認してください。

- 「参加人数を保存」を押した
- 保存完了メッセージが表示された
- ページを再読み込みした
- 別のSupabaseプロジェクトへ保存していない
- NetworkのRequest URLが正しいSupabaseを指している

正常時は、参加人数に連動して次が変わります。

- 全札数
- 未回答数
- 未回答札番号
- 札番号の入力上限
- 有効な固有QRの範囲
- 主催者番号

---

## 回答を修正したら回答件数が増えた

回答修正は、新しい回答の追加ではなく、既存回答の更新でなければなりません。

確認する仕様は次のとおりです。

```text
初回回答：INSERT
回答修正：UPDATE
```

`ticket_number`の一意制約を削除しないでください。

修正後は、回答内容が変わり、回答済み数が増えていないことを確認します。

---

## 3種類マッチまたは完全一致が正しくない

### 3種類マッチ

3つの商品番号が同じ場合に成立します。配合量は判定に含めません。

### 完全一致

3つの商品番号と、それぞれの配合量が同じ場合に成立します。

確認用として、次の3回答を登録すると切り分けやすくなります。

1. 基準となる回答
2. 同じ3種類で配合量が異なる回答
3. 同じ3種類で配合量も同じ回答

期待結果：

- 3人とも3種類マッチへ表示
- 基準回答と3番目だけ完全一致へ表示

テスト後は回答を全削除してください。

---

## QR番号が違う

次を確認してください。

- QRの公開URLがProductionの固定URLになっている
- `ticket`番号と印刷番号が一致している
- 古いQRを印刷していない
- 参加人数変更後に必要なQRを作り直した
- QR検査を実行した

QR生成スクリプト：

```text
scripts/generate-qr.mjs
```

QR検査スクリプト：

```text
scripts/verify-qr.mjs
```

可能であれば次を実行します。

```bash
npm run verify:qr
```

## エラーをAIへ相談するとき

次の情報を伝えてください。

- どのサービスを開いているか
- 本番用かテスト用か
- どの操作をしたか
- 画面に表示されたエラー全文
- VercelのDeploymentが`Ready`か
- Supabaseプロジェクトが`Healthy`か
- ConsoleまたはNetworkのエラー内容

次の情報は隠してください。

- パスワード
- 復旧コード
- Secret key
- service_roleキー
- アクセストークン
- 管理者UID
- 個人情報を含む回答データ

Publishable keyも、スクリーンショットでは隠すことを推奨します。

---

## 解決後の確認

原因を修正した後は、問題があった機能だけでなく、次も確認してください。

- アプリが正常に表示される
- 集計者がログインできる
- 参加人数を保存できる
- 再読み込み後も参加人数が維持される
- 初回回答を保存できる
- 回答済み状態を復元できる
- 回答を修正できる
- 修正しても回答件数が増えない
- 未回答番号が正しい
- ランキングが正しい
- 3種類マッチが正しい
- 完全一致が正しい
- 発表モードが動く
- 全回答を削除できる

問題が解決したら、原因と対応内容をGitHubの変更説明や引き継ぎ資料へ記録してください。
