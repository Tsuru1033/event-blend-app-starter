# 本番前テスト

本番前に、アプリ、Supabase、Vercel、QRコードが正しく動くことを確認します。

テスト中に登録した回答は、確認完了後に必ず削除してください。

---

## 1. 公開状態を確認する

- [ ] Vercelの対象アプリが`Ready`になっている
- [ ] Productionの固定URLからアプリを開ける
- [ ] アプリの画面が真っ白にならない
- [ ] イベント名が正しい
- [ ] 商品番号と商品名が正しい
- [ ] ベース量、合計量、選択可能な配合量が正しい
- [ ] 参加者と集計者の切り替えが表示される

---

## 2. Supabaseとの接続を確認する

- [ ] Supabaseプロジェクトが停止していない
- [ ] Vercelに`VITE_SUPABASE_URL`が登録されている
- [ ] Vercelに`VITE_SUPABASE_PUBLISHABLE_KEY`が登録されている
- [ ] Project URLとPublishable keyを同じSupabaseプロジェクトから取得した
- [ ] Secret keyやservice_roleキーをブラウザー用に使用していない
- [ ] 環境変数を変更した後にProductionを再デプロイした

集計者がログインできない場合は、パスワードを変更する前に、SupabaseのProject URLとブラウザーのNetworkに表示されるRequest URLが一致しているか確認してください。

---

## 3. 集計者ログインを確認する

- [ ] SupabaseのAuthenticationに集計者ユーザーが存在する
- [ ] 集計者のメールアドレスとパスワードを安全な場所に保管した
- [ ] 集計者ユーザーが確認済みになっている
- [ ] アプリの集計者画面からログインできる
- [ ] ログイン後に「イベント設定」が表示される
- [ ] ログアウトできる

---

## 4. 参加人数を確認する

このアプリは最大30名まで対応しています。

今回の参加人数を集計者画面から設定してください。

```text
集計者
→ イベント設定
→ 今回の参加人数
→ 参加人数を保存
```

- [ ] 1～30名の範囲で参加人数を入力できる
- [ ] 「参加人数を保存」を押せる
- [ ] 保存完了メッセージが表示される
- [ ] 全札数が設定人数へ変わる
- [ ] 未回答数が設定人数を基準に表示される
- [ ] 主催者番号が参加人数と同じ番号になる
- [ ] ページを再読み込みしても設定人数が維持される
- [ ] 別の端末から開いても同じ人数が反映される

### 境界番号の確認

20名で運用する場合の例です。

- [ ] `?ticket=20`を開くと、札番号20が固有QRとして認識される
- [ ] `?ticket=21`を開くと、札番号21が固定表示されない
- [ ] 札番号の手入力欄が「1から20」と表示される
- [ ] 21以上では回答確認ボタンが有効にならない

参加人数が20名以外の場合は、設定人数と、その次の番号で同じ確認をしてください。

## 5. QRコードを確認する

- [ ] 固有QRが1番から参加人数分まで揃っている
- [ ] 欠番がない
- [ ] 重複番号がない
- [ ] 印刷されている札番号とQR内の`ticket`番号が一致する
- [ ] 最初の固有QRを読み取れる
- [ ] 最後の固有QRを読み取れる
- [ ] マスターQRを読み取れる
- [ ] マスターQRから札番号を手入力できる
- [ ] QRのURLが今回使用するProductionの固定URLになっている

QRを変更した場合は、可能であれば次を実行してください。

```bash
npm run verify:qr
```
