# QRコードを作成する

このガイドでは、公開したアプリのURLを使って、参加者用の固有QRとマスターQRを作成し、内容を検査する方法を説明します。

---

## 作成するQRコード

### 固有QR

参加者ごとに異なる札番号を含むQRコードです。

```text
https://公開URL/?ticket=札番号
```

20名の場合は、札番号1から20までの20枚を作成します。

### マスターQR

札番号を含まない共通QRコードです。

```text
https://公開URL/
```

マスターQRから開いた場合、参加者は手元の札番号を入力します。

---

## QRコードを作る前に確認すること

- [ ] VercelのProduction固定URLが分かっている
- [ ] Vercelの状態が`Ready`になっている
- [ ] 公開URLからアプリを開ける
- [ ] 集計者画面で今回の参加人数を保存した
- [ ] 再読み込み後も参加人数が維持される
- [ ] QRへ使う参加人数と、集計者画面の人数が一致している

プレビュー用の長いURLではなく、次のようなProduction固定URLを使用してください。

```text
https://アプリ名.vercel.app
```

---

## 使用するファイル

QR生成用のファイルです。

```text
scripts/generate-qr.mjs
```

生成したQRを読み取り検査するファイルです。

```text
scripts/verify-qr.mjs
```

必要なコマンドは`package.json`へ登録されています。

```text
generate:qr
verify:qr
```

---

## 必要な環境

QR生成には、Node.jsとコマンド操作ができる環境が必要です。

利用者がコマンド操作に慣れていない場合は、AIへ次のように依頼してください。

```text
私はコマンド操作の初心者です。

scripts/generate-qr.mjsとscripts/verify-qr.mjsを確認し、公開URLと参加人数を確認してから、QR生成と検査を一操作ずつ案内してください。

パスワードや秘密キーは使用しないでください。
```

---

## 1. アプリのファイルをパソコンへ用意する

GitHubで自分専用のアプリ保管ページを開きます。

次の順に進みます。

```text
Code
→ Download ZIP
```

ダウンロードしたZIPを右クリックし、次を選びます。

```text
すべて展開
```

展開後のフォルダーを開いてください。

次のファイルが見える場所が、コマンドを実行する場所です。

```text
package.json
scripts
src
```

---

## 2. 必要なライブラリを準備する

展開したフォルダーでターミナルを開き、次を実行します。

```bash
npm install
```

処理が完了するまで待ってください。

エラーが表示された場合は、エラー全文をAIへ送ってください。ただし、ユーザー名や個人情報が表示される部分は隠してください。

---

## 3. 固有QRとマスターQRを生成する

### Windows PowerShellの場合

20名で作成する例です。

```powershell
$env:QR_BASE_URL="https://アプリ名.vercel.app"
$env:QR_TOTAL_TICKETS="20"
npm run generate:qr
```

### Windowsコマンドプロンプトの場合

```bat
set QR_BASE_URL=https://アプリ名.vercel.app
set QR_TOTAL_TICKETS=20
npm run generate:qr
```

### macOS・Linuxの場合

```bash
QR_BASE_URL=https://アプリ名.vercel.app QR_TOTAL_TICKETS=20 npm run generate:qr
```

`https://アプリ名.vercel.app`は、実際のProduction固定URLへ置き換えてください。

`20`は、今回の参加人数へ置き換えてください。

---

## 4. 生成成功を確認する

正常に完了すると、次のようなメッセージが表示されます。

```text
20枚の固有QRとマスターQRを生成しました。
生成先：output/qr/
```

生成先は次です。

```text
output/qr/
```

20名の場合、主に次のファイルが作成されます。

```text
ticket-01.png
ticket-02.png
...
ticket-20.png
master.png
```

QR番号、URL、ファイル名の対応情報は次へ保存されます。

```text
output/qr-manifest.json
```

---

## 5. QRコードを検査する

生成後、次を実行してください。

```bash
npm run verify:qr
```

正常な場合は、各QRについて`OK`が表示され、最後に次が表示されます。

```text
すべてのQRが正常です。
```

検査では次を確認します。

- QR画像ファイルが存在する
- QRを機械的に読み取れる
- 読み取ったURLが予定URLと一致する
- 札番号とURL内の`ticket`番号が一致する
- マスターQRが札番号を含まない公開URLを示す

`NG`またはエラーが1件でも表示された場合は、そのQRを印刷しないでください。

---

## 6. 目視でも確認する

自動検査後、スマートフォンで次を読み取ってください。

- [ ] 札番号1のQR
- [ ] 最後の札番号のQR
- [ ] マスターQR

20名の場合は、次を確認します。

### 札番号1

```text
https://アプリ名.vercel.app/?ticket=1
```

アプリで札番号1が固定表示されることを確認します。

### 札番号20

```text
https://アプリ名.vercel.app/?ticket=20
```

アプリで札番号20が固定表示されることを確認します。

### 札番号21

20名設定の場合、札番号21は対象外です。

```text
https://アプリ名.vercel.app/?ticket=21
```

札番号21が固定表示されず、入力欄が「1から20」になれば正常です。

### マスターQR

マスターQRから開いた場合は、札番号が固定されず、手入力欄が表示されることを確認します。

---

## 7. QR番号札へ配置する

印刷物には、QRコードと札番号を明確に表示してください。

```text
札番号 1
QR画像 ticket-01.png
```

番号とQR画像を取り違えないように、`qr-manifest.json`と照合してください。

推奨事項：

- 札番号を大きく表示する
- QRの周囲に余白を残す
- QRを小さくしすぎない
- 光沢の強い用紙を避ける
- 切り取り位置でQRを欠損させない
- 印刷後に実物をスマートフォンで読み取る

---

## 参加人数を変更した場合

集計者画面で参加人数を変更しても、すでに印刷したQR番号札は自動では変わりません。

参加人数を変更した場合は、必要な番号分のQRをあらためて生成してください。

例：30名から20名へ変更した場合

- 使用する固有QR：1～20
- 21～30のQR：使用しない
- マスターQR：公開URLが同じなら継続使用可能

イベントごとに公開URLが変わる場合は、マスターQRも再生成してください。

---

## QR生成時によくある間違い

### 公開URLが違う

VercelのProduction固定URLを使用してください。

次のような一時的なプレビューURLを使わないでください。

```text
https://アプリ名-英数字-ユーザー名.vercel.app
```

### 末尾に不要なパスがある

基本URLは次の形式にします。

```text
https://アプリ名.vercel.app
```

固有QRの`/?ticket=番号`はスクリプトが自動で追加します。

### 参加人数が一致していない

次の2つを一致させてください。

- 集計者画面で保存した今回の参加人数
- `QR_TOTAL_TICKETS`へ指定する人数

### 古いQRを印刷している

生成日時と公開URLを確認し、古いフォルダーのQRを使わないでください。

---

## コマンドが動かない場合

### `npm`が見つからない

Node.jsがインストールされていない可能性があります。

AIへ、Node.jsの公式配布元から安全に導入する手順を案内してもらってください。

### `QR_BASE_URLを指定してください`と表示される

公開URLが環境変数へ設定されていません。

使用している画面がPowerShell、コマンドプロンプト、macOS・Linuxのどれかを確認し、該当するコマンドを使用してください。

### `QR_TOTAL_TICKETSは1～100の整数`と表示される

参加人数の入力形式を確認してください。

このアプリの最大対応人数は30名なので、1～30の整数を使用してください。

### QR検査で`NG`になる

次を確認してください。

- 生成した画像が削除・移動されていない
- `qr-manifest.json`が同じ生成結果のもの
- 公開URLが正しい
- QRを生成し直した後に検査した

---

## 秘密情報について

QR生成に必要なのは、Productionの公開URLと参加人数だけです。

次の情報は不要です。

- SupabaseのSecret key
- service_roleキー
- データベースパスワード
- 集計者のパスワード
- GitHubアクセストークン
- Vercelアクセストークン

これらをコマンド、QR、ファイル、AIとのチャットへ入れないでください。

- [ ] 1番から参加人数分まで作成された

- [ ] 印刷番号とQR画像の対応を確認した
- [ ] 印刷後の実物を読み取った

すべて確認できたら、QRコードの準備は完了です。
